# SupaNails — Booking Website

A React + Vite + Tailwind website for SupaNails, with a full multi-step
booking flow. Built to run on Vercel and to be editable in Lovable.

## Running locally

```bash
npm install
npm run dev
```

Build for production:

```bash
npm run build
```

## Booking flow

The booking page (`/book`) is a single scrolling form, not a step wizard:

1. **Service Selections** — category tabs (Nail Services / Toe Services /
   Hands + Toes), then a rich dropdown of that category's services with
   duration, a "recommended for" note, and price.
2. **Custom Sculpt Properties** *(hands/combo only)* — nail length and art
   complexity add-ons (each adds to the running total), plus an optional
   design inspiration image upload.
   - **2b. Select Your Toe Service** *(combo only)* — adds a toe service on
     top; the quote becomes hand price + add-ons + toe price.
3. **Proposed Slot Time** — a WhatsApp "squeeze-in appointment" note, a date
   picker (blocks past dates), then a live grid of the day's 1-hour slots.
4. **Client Details** — name, WhatsApp number, optional email, and a free-text
   comments field for bespoke requests.
5. **Confirm Your Deposit** — collapsible bank details and a required payment
   screenshot upload (plus an optional reference field).
6. **Salon Slot Policies** — deposit, lateness, one-client-per-slot, and
   clean-nails policies, with a required "I accept" checkbox.
7. **Review & Confirm** — running total, summary, and the submit button.

All of `src/data/services.js` (service names, durations, "recommended for"
text, prices) and the nail-length/art-complexity add-on amounts are
placeholders modeled on a reference flow the client shared — replace them
with SupaNails' real menu and pricing.

## What's a placeholder right now

Nothing here was invented as real business fact. Replace before launch:

- **Services & prices** — `src/data/services.js`
- **Bank details & deposit amount** — `src/data/config.js`
- **Phone / email / address / Instagram / WhatsApp** — set as env vars (see `.env.example`)
- **Photos** — drop real images into `public/images/`:
  - `public/images/hero-placeholder.jpg` (homepage hero)
  - `public/images/gallery/photo-1.jpg` … `photo-8.jpg` (gallery — add/remove
    entries in `src/components/Gallery.jsx`'s `galleryImages` array to match)
- **About page copy** — `src/pages/About.jsx`

Until real values are set, the UI shows clearly marked placeholder text so
nothing looks like a real claim (no invented founder, no invented years of
experience, no fake prices presented as final).

## Connecting the booking backend (Make.com)

The site never talks to Google Sheets/Calendar directly — everything goes
through two Make.com webhooks, kept in one file: `src/lib/api.js`. Set their
URLs as environment variables (copy `.env.example` to `.env` locally, and add
the same variables in Vercel's project settings):

```
VITE_AVAILABILITY_WEBHOOK_URL=...
VITE_BOOKING_WEBHOOK_URL=...
```

**Scenario 1 — Availability** (GET webhook, called with `?date=YYYY-MM-DD`)
1. Custom Webhook trigger (GET).
2. Google Sheets — Search Rows: bookings on that date with status = confirmed.
3. Google Calendar — Search Events: events on that date.
4. Merge both sets of times into one array of "HH:mm" strings.
5. Webhook response: `{ "bookedSlots": ["14:00", "15:00"] }`

**Scenario 2 — Create booking** (POST webhook)

> ⚠️ **Easy-to-miss step that breaks the confirmation screen**: Make.com's
> webhook, by default (with no "Webhook response" module added), replies
> with the plain text `Accepted` — not JSON. If your scenario doesn't end
> with an explicit **Webhooks → Webhook response** module, the website will
> still show the confirmation screen (it no longer depends on Make's
> response being valid JSON — see below), but you will NOT be able to
> report a double-booking conflict back to the browser. Add that module as
> the last step of both the "taken" and "free" branches for full behavior.

1. Custom Webhook trigger (POST), receiving the JSON body sent by
   `submitBooking()` in `src/lib/api.js`:
   `bookingId` — generated by the website in the shape `"SUP-2026427"`
   (`SUP-` + year + any 3 digits). Use this as the booking reference when
   writing the Sheets row, the Calendar event, and both emails. If you'd
   rather have Make generate its own instead, return it as `bookingId` in
   the Webhook response (step 4f below) — `api.js` prefers whatever Make
   sends back over its own.

   The rest of the payload: `category`,
   `service` (name), `quote` (total in Naira), `nailLength`,
   `artComplexity`, `inspirationImage` (base64 data URL or null), `dateISO`,
   `time`, `customer` (`name`, `whatsapp`, `email`, `comments`),
   `paymentReference`, `paymentScreenshot` (base64 data URL, required),
   `deposit`.
2. Google Sheets — Search Rows: check whether that exact date + time is
   already a confirmed row.
3. Google Calendar — Search Events: check the same date/time isn't inside a
   BUSY event.
4. Router:
   - **If taken** → Webhook response: `{ "success": false, "reason": "slot_taken" }`
   - **If free** → continue:
     a. For each file field (`inspirationImage`, `paymentScreenshot`), add a
        **Tools — Convert to binary data** module (or Make's built-in
        "Base64 → Binary" function inside a Set Variable step) to turn the
        base64 string into actual binary data Make can attach to things.
        Two ways to use that binary data, pick one or both:
        - **Attach directly to the owner's email** (what you need right
          now): in the **Email — Send an email** module below, add it under
          Attachments, with the filename and the converted binary data as
          the value.
        - **Also keep a permanent copy**: Google Drive — Upload File with
          that same binary data, then store the resulting Drive link in the
          Sheets row instead of (or alongside) the attachment.
     b. Google Sheets — Add Row (Booking ID, Customer Name, WhatsApp, Email,
        Service, Category, Quote, Nail Length, Art Complexity, Appointment
        Date, Appointment Time, Deposit, Payment Reference, Payment
        Screenshot link, Inspiration Image link, Comments, Booking Status,
        Created At).
     c. Google Calendar — Create Event, title
        `SupaNails — {{Customer Name}} — {{Service}}`, description containing
        WhatsApp number, email, service, quote, payment reference, and
        booking ID, timezone `Africa/Lagos`.
     d. **Email — Send an email** to SupaNails with the new-booking details
        (customer name, WhatsApp, service, date/time, deposit, payment
        reference) — attach the nail reference photo and deposit screenshot
        here, per step (a) above.
     e. Email — send the customer their confirmation (if an email was given).
     f. Webhook response: `{ "success": true, "bookingId": "SUP-..." }`

Until these webhooks are connected, the site runs in a safe demo mode: every
date shows as fully open, and confirming a booking simulates success with a
`SN-DEMO-xxxxx` reference, so the flow can be reviewed end-to-end before the
backend exists.

## Project structure

```
src/
  components/          Navbar, Footer, Hero, ServiceCard, Gallery
  components/booking/  the 7-step booking flow (one file per step)
  context/             BookingContext — shared state across booking steps
  data/                config.js (business info), services.js (menu)
  lib/                 api.js (Make.com calls), dates.js (Africa/Lagos helpers)
  pages/               Home, Services, GalleryPage, About, Book
```

## Deploying

- **Vercel**: push to a Git repo, import into Vercel, set the two webhook env
  vars (and the contact env vars if you want them, otherwise placeholders
  show), deploy.
- **Lovable**: import this repo/folder — it's a standard Vite + React +
  Tailwind project with no Supabase dependency.
